Reviewer path

One capsule. Three checks. One next gate.

The public path is intentionally short. A qualified reviewer should be able to identify the source, comparator, metric, configuration, result, adverse finding, limitation, and decision without reconstructing the entire platform.

01

Inspect the canonical capsule

Read what was tested, the authoritative source, the incumbent baseline, the metric locked before scoring, and the exact limitation.

  • Declared run type and decision owner
  • Source and output hash records
  • Positive and negative findings
  • Claim boundary and next gate
Inspect capsule
02

Verify the declared artifacts

Run the repository verifier and focused tests from a clean checkout. Verification checks declared structure and hashes; it does not independently reproduce a private experiment.

  • Schema and required fields
  • Path and hash integrity
  • Metric-lock and negative-result controls
  • Fail-closed handling of tampering
Run quick start
03

Make a bounded decision

A valid evidence packet does not force promotion. The reviewer selects the next authorized state based on the substantive evidence and open authority gates.

  • Reject the claim
  • Request information or correct the design
  • Rerun under predeclared conditions
  • Authorize external review or a scoped pilot

Current public fixture

A bounded EIA/Kraken replay summary with the failure cost retained.

The public example demonstrates the evidence method on frozen time-series stress windows. It is not represented as a field-deployed utility system, a trading performance record, or an independently reproduced scientific result.

What is declared

Reviewer-readable inputs and outputs

  • Named public-source context and a frozen source summary
  • A predeclared metric and incumbent comparison
  • Hash records for the declared public artifact
  • Positive and negative metrics, including false-rejection cost
  • A pilot decision of external_review
What remains open

Substantive reproduction and field relevance

  • The underlying private replay has not been independently reproduced
  • No utility, laboratory, agency, or buyer has endorsed the result
  • No field savings, live deployment, or production performance is claimed
  • No hash proves the scientific truth of an arbitrary claim
  • No result authorizes live trading or operational control
Integrity is necessary but not sufficient. A file can be authentic and still be incomplete, irrelevant, poorly designed, or unauthorized for promotion. LumenCore preserves that distinction.

Controlled external-validation gate

The next serious test belongs to the reviewer who controls the data and decision.

External validation should not be simulated through stronger language. It requires an authorized environment, agreed comparator, locked acceptance criteria, preserved failures, and a human-approved release decision.

Gate 01

Confirm authority and data rights

Name the authoritative source, permitted use, responsible reviewer, disclosure boundary, and any controlled-data restrictions.

Gate 02

Lock the incumbent and acceptance rule

Freeze the comparator, metric, threshold, window, exclusions, uncertainty treatment, and failure conditions before scoring.

Gate 03

Run and preserve every outcome

Retain positive, neutral, incomplete, and adverse findings with configuration, version, source identity, and hashes.

Gate 04

Issue one bounded decision

Reject, rerun, request information, authorize the next external review, or scope a pilot with written acceptance and stop conditions.

Move from review to controlled test

Use the public method on one buyer-owned claim.

A commercial engagement begins with a fit check and written scope. No performance, savings, certification, funding, procurement, or deployment outcome is guaranteed.

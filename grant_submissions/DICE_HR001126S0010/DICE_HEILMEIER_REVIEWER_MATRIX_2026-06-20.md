## Purpose

This matrix turns the DICE package into direct answers to the questions a DARPA
reviewer is likely to ask first:

- What is the technical bet?
- Why does it matter now?
- What is new compared with normal multi-agent orchestration?
- What evidence exists today?
- What still needs to be proven?
- What are the tests, risks, costs, and transition hooks?

The strongest claim is not that LumenCore has already solved DICE. The strongest
claim is that the package defines a measurable, bounded Phase I experiment for
controlled emergence in heterogeneous agent teams, with frozen local evidence,
explicit failure modes, and a clear path from synthetic harness to adversarial
team evaluation.

## Highest-Value Reviewer Claims

Use these claims because they are valuable and defensible:

1. LumenCore frames controlled emergence as a measurable coordination problem,
   not a vague autonomy claim.
2. The package distinguishes TA1 coordination behavior from TA2 local control
   behavior and proposes metrics for both.
3. Constraint contracts give each agent assignment a machine-checkable envelope:
   role, horizon, evidence lineage, expiration, constraint set, and risk state.
4. Frozen local runs provide preliminary evidence that the harness can generate,
   compare, and hash bounded coordination/control artifacts.
5. The live-breadth replay lane shows a path from controlled synthetic tests to
   real pulled time-series stress windows while preserving the boundary that
   replay labels are derived, not native DICE ground truth.
6. The provenance-gated live-breadth annex shows the measurement system now
   separates promoted live-measured evidence from context-only estimates and
   anchors the promoted signal in the frozen truth chain.
7. The proposal explicitly names transfer, collusion, cost, and governance risks
   instead of burying them.
8. The work is structured so Phase I can fail usefully: each failure mode maps
   to a measurable gate and an ablation.

## Program-Fit Logic

The DICE fit is strongest when described as a Phase I measurement program:

1. Establish baselines for centralized orchestration, decentralized task-market
   coordination, and uncontrolled emergent teams.
2. Insert constraint contracts into the coordination loop.
3. Give local controllers a bounded challenge/reject/recover mechanism.
4. Measure whether the combined loop improves mission success, communication
   efficiency, recovery behavior, role coherence, and alignment under drift.
5. Stress the system with collusion, stale evidence, role poisoning, and compute
   budget pressure.

That framing is credible because it invites hard tests. It does not ask the
reviewer to believe a finished system already exists.

| Cost/performance | vLLM/open-weight stack, smaller/larger models, local/cloud inference | Is the control loop affordable at scale? | Measure latency, tokens, GPU hours, and marginal cost per successful mission. |

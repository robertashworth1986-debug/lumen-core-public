## 7. BAAT packaging and file-control gate

DARPA's general BAAT instructions state that unclassified proposals submitted through BAAT are uploaded as a single `.zip` or `.zipx` archive, with a maximum archive size of **100 MB**. Only one archive is accepted per submission; a later upload for the same submission can overwrite the prior upload.

### Controlled packaging sequence

1. Create a clean release directory that contains only candidate submission files.
2. Remove comments, tracked changes, hidden text, personal metadata, unresolved placeholders, template instructions, and broken links.
3. Validate every file independently at 100% zoom.
4. Confirm filenames and formats against the current templates and BAAT workspace.
5. Create a release manifest containing filename, bytes, SHA-256, page count, document owner, and approval state.
6. Secret-scan and malware-scan the release directory.
7. Produce the single final archive and record its SHA-256 and byte size.
8. Upload only after explicit approval to access the final workspace and accept applicable notices.
9. Validate portal preview, fields, totals, and file list without clicking Submit.
10. Obtain explicit founder approval for the exact uploaded package and every representation/certification.
11. Click Submit only in an explicitly approved active session.

### File-level checks

- required official template used;
- correct output type;
- readable fonts and legible figures/tables;
- compliant page count, margins, and markings;
- correct abstract ID and title where requested;
- no credentials, tokens, account identifiers, private portal images, or secrets;
- no confidential patent-enabling detail in public-facing attachments;
- exact release hash matches the file uploaded.
